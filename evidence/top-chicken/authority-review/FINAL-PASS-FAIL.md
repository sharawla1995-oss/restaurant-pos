## التغيير الأمني وحدوده

أُلغي استخدام Profile defaults كمنحة. البوابة تقرأ قرار Cloud الحالي لكل عملية، وتضيف منعًا صريحًا عند تعطيل feature أو module أو business/profile. لا تُنسخ صلاحية دائمة إلى Beta. مفتاح Central الخدمي يبقى في Central؛ المقترح قناة خاصة بـTC فقط بمفتاح API عام وسر HMAC مستقل. SQL لا يقبل سياق الصلاحية من مستخدم authenticated مباشرة، ويظل فحص الموظف والنشاط والفرع عند الدوال الأصلية.

قاعدة Cloud الحالية تعيد **14 صلاحية core مسموحة و16 صلاحية تجارية `NOT_ENTITLED`**، ومنها orders/delivery/pickup. Modules المفعلة لا تمنح حق تجاوز هذه النتيجة. لم أغيّر أي منحة، والاختبارات الإيجابية التجارية تستخدم منحًا اصطناعية فقط. يلزم قرار المالك عبر مسار Cloud التجاري المعتمد قبل السماح بتشغيل هذه الوظائف.

تعطيل Cloud يمنع العملية التالية التي تقرأ القرار. يوجد حد أقصى **10 ثوانٍ** للعملية التي سبق قبول قرارها، بسبب فصل Cloud وBeta؛ لا يوجد ادعاء بإلغاء لحظي ذري بين القاعدتين. الانتهاء يُفحص أيضًا بعد الكتابة ويلغي المعاملة كاملة. إيقاف بوابة TC ينتظر العمليات المقبولة ثم يمنع الجديدة. لم تُراجع كل واجهات المخزون أو RPCs القديمة أو استقبال الموقع ضمن هذه الجولة؛ لا يُستخدم التقرير لتبرير فتحها.

إصلاح أرقام الدفعات يحتفظ بخمس جمل INSERT الأصلية للأنشطة الأخرى حرفيًا، بدل تمرير NULL إلى أعمدة identity. فرع TC وحده يضيف الرقم والهوية المطلوبة. لم يُعد ربط singleton الذي يخص نشاطًا آخر.
